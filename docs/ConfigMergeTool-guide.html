configmergetool 3.0.2 · installation & user guide

ConfigMergeTool 3.0

Installs into your own home folder in about two minutes. You don't need administrator rights, and nothing is written to system directories. It then audits configuration drift across nodes and merges site settings into new releases.

Python 3.9+ 2 required libraries: openpyxl, PyYAML no admin / sudo no network at run time macOS · Linux · Windows
New in 3.0.2
  • Audit compares YAML files (Helm values.yaml) by structure: one row per parameter, and entries in a different order are no longer flagged.
  • values.yaml is the final version: other values* files next to it are skipped as backups. values.schema.json is still audited.
  • Merge now merges YAML with the site values winning (it used to copy the release file and lose them), and no longer deploys backup copies.
  • PyYAML is a new required library. For servers without internet there is a RHEL 8/9 offline bundle.

Upgrading from 3.0.1 is a pip upgrade. Audit totals for YAML files change, because each differing parameter is now its own row.

Everything else the tool uses comes from the Python standard library: argparse, json, xml, difflib, hashlib, html, logging, pathlib, re, shutil, tempfile, fnmatch, dataclasses, datetime, collections, urllib.

To read the results

  • A web browser (Chrome, Edge, Firefox or Safari) for audit_report.html and merge_diff.html. Each report is a single self-contained file that works offline.
  • A spreadsheet program (Excel, LibreOffice Calc or Numbers) for the .xlsx reports.
Checking your Python

Run python3 --version on macOS/Linux, or py --version on Windows. If it prints 3.9 or higher, you're ready. If Python is missing, install it once from python.org. On Windows, leave "Install for all users" unticked in the installer: a per-user install needs no administrator rights.

Choose an install method

Every method below installs into your home folder. None of them uses sudo, Administrator rights, or the system Python's package folders.

RECOMMENDED

A · Virtual environment in your home folder

A folder you choose, such as ~/venv (/home/user/venv). Isolated from the system Python; see exactly what goes where. Works everywhere, including Homebrew and Debian/Ubuntu Pythons that block pip --user.

ALTERNATIVE

B · pip --user

Installs into your per-user Python folder. Quick, but refused by "externally managed" Pythons (Homebrew, recent Debian/Ubuntu) and shared with your other user packages.

NO INTERNET

C · Offline server

Download the wheel and its libraries once on a connected machine, copy them over, and install with method A. No network access is needed on the server.

NO INSTALL

D · Run from source

Run python3 ConfigMergeTool.py from a copy of the source folder. openpyxl still has to be installed somewhere, for example a home-folder venv.

Install into a folder you choose

A virtual environment puts everything under one folder you pick: the tool, its libraries, and a private copy of the Python and pip commands. Nothing goes to /usr, /opt, /etc, C:\Program Files or the system Python's site-packages, and no admin rights are needed. The examples use ~/venv, which is /home/user/venv on Linux and /Users/<you>/venv on macOS. Any folder you can write to works the same way.

macOS / Linux — any folder
INSTALL_DIR=~/venv                      # or /home/user/tools/cmt, /data/apps/cmt, …
[ -x "$INSTALL_DIR/bin/python" ] || python3 -m venv "$INSTALL_DIR"   # reuse it if it already exists
"$INSTALL_DIR/bin/pip" install --no-cache-dir "configmergetool-3.0.2-py3-none-any.whl[encoding]"
"$INSTALL_DIR/bin/configmergetool" --version   # configmergetool 3.0.2
windows powershell — any folder
$InstallDir = "$env:USERPROFILE\venv"     # or D:\tools\cmt, …
if (-not (Test-Path "$InstallDir\Scripts\python.exe")) { py -m venv $InstallDir }
& "$InstallDir\Scripts\pip.exe" install --no-cache-dir "configmergetool-3.0.2-py3-none-any.whl[encoding]"
& "$InstallDir\Scripts\configmergetool.exe" --version

Run the command from anywhere

Link only the configmergetool command into a folder that's already on your PATH:

macOS / Linux
mkdir -p ~/.local/bin
ln -sf ~/venv/bin/configmergetool ~/.local/bin/configmergetool
# only if ~/.local/bin is not on PATH yet (zsh: ~/.zshrc, bash: ~/.bashrc)
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc && source ~/.zshrc
Don't put the whole ~/venv/bin on your PATH permanently

That folder also contains python3 and pip, which would then replace your normal ones in every terminal. To use the whole environment for one session, run source ~/venv/bin/activate, and deactivate when you're done.

Rules for the install folder

  • Create it where it will stay. The scripts in bin/ record the folder's full path, so a moved or copied folder fails with bad interpreter. To move it, delete it and create it again at the new path.
  • It depends on the Python that created it (the home line in pyvenv.cfg). If that Python is removed, or upgraded to a new minor version such as 3.14 → 3.15, recreate the folder and reinstall.
  • Shared folder: if ~/venv also holds other tools, upgrading or uninstalling ConfigMergeTool touches only its own packages (and openpyxl or chardet if a newer version is required). Uninstall with ~/venv/bin/pip uninstall configmergetool. Delete the whole folder only if nothing else lives in it.

Why not pip --prefix or --target?

Both can also write into a folder of your choice, but both were less reliable when tested:

  • pip install --prefix DIR skipped openpyxl and et_xmlfile because the system Python already had them. The folder then only works on machines that have those libraries too, and only with PYTHONPATH=DIR/lib/python3.X/site-packages set.
  • pip install --target DIR installs every library, but runs only with PYTHONPATH=DIR set, and its command script is tied to the system Python's path.

A · Install into a virtual environment in your home folder

Copy configmergetool-3.0.2-py3-none-any.whl to your machine first. It's in the dist/ folder of the source tree and attached to the GitHub release v3.0.2.

  1. Create the environment in your home folder. Skip this if ~/venv already exists; the tool is simply added to it:
    terminal
    python3 -m venv ~/venv
  2. Install the wheel into it. [encoding] also installs chardet, which is recommended when sites have files that aren't UTF-8:
    terminal
    ~/venv/bin/pip install "configmergetool-3.0.2-py3-none-any.whl[encoding]"
  3. Put the command on your PATH, so you can type configmergetool from any folder. This links it into ~/.local/bin, which is in your home folder:
    terminal
    mkdir -p ~/.local/bin
ln -sf ~/venv/bin/configmergetool ~/.local/bin/configmergetool
# If ~/.local/bin is not on your PATH yet (zsh = macOS default; use ~/.bashrc for bash):
echo 'export PATH="$HOME/.local/bin:$PATH"' >> ~/.zshrc && source ~/.zshrc
  4. Check it: configmergetool --version should print configmergetool 3.0.2.
No activation needed

With the link from step 3, you never need to run source …/activate. If you prefer activating, run source ~/venv/bin/activate, then use configmergetool and pip directly; deactivate leaves it.

  1. Open PowerShell as yourself, not as Administrator, and create the environment in your profile folder (skip this if it already exists):
    powershell
    py -m venv "$env:USERPROFILE\venv"
  2. Install the wheel, from the folder where you saved it:
    powershell
    & "$env:USERPROFILE\venv\Scripts\pip.exe" install "configmergetool-3.0.2-py3-none-any.whl[encoding]"
  3. Add its Scripts folder to your own PATH. This is a per-user setting, and no admin is needed. Then open a new PowerShell window:
    powershell
    $dir = "$env:USERPROFILE\venv\Scripts"
[Environment]::SetEnvironmentVariable("Path", [Environment]::GetEnvironmentVariable("Path","User") + ";$dir", "User")
  4. Check it in the new window: configmergetool --version should print configmergetool 3.0.2.
Prefer activating?

Run & "$env:USERPROFILE\venv\Scripts\Activate.ps1". If PowerShell refuses to run scripts, allow them for your account only, which needs no Administrator rights: Set-ExecutionPolicy -Scope CurrentUser RemoteSigned. Command Prompt users can run %USERPROFILE%\venv\Scripts\activate.bat instead.

B · Install with pip --user

This installs into your per-user Python folder (see where files end up). Use it only when method A isn't an option.

macOS / Linux
python3 -m pip install --user "configmergetool-3.0.2-py3-none-any.whl[encoding]"
python3 -m site --user-base   # prints the base folder; the command is in its bin/ subfolder
windows powershell
py -m pip install --user "configmergetool-3.0.2-py3-none-any.whl[encoding]"
py -m site --user-site      # the command is in the sibling Scripts\ folder

If configmergetool isn't found afterwards, add the user bin or Scripts folder to your PATH, the same way as in method A step 3.

"error: externally-managed-environment"

Homebrew Python on macOS and recent Debian/Ubuntu system Pythons refuse pip --user on purpose, so that user packages can't break the operating system's Python. Use method A instead. Don't add --break-system-packages.

C · Install on a server without internet access

Production nodes often can't reach the internet. Download the wheel and its libraries once on a connected machine, copy the folder to the server, and install from it. This procedure was tested with --no-index, so pip never contacts a package index.

  1. On a connected machine, collect the wheel and its libraries into one folder:
    connected machine
    mkdir wheelhouse
cp configmergetool-3.0.2-py3-none-any.whl wheelhouse/
python3 -m pip download -d wheelhouse "wheelhouse/configmergetool-3.0.2-py3-none-any.whl[encoding]"
    The folder then holds configmergetool-3.0.2-py3-none-any.whl, openpyxl-3.1.5-py2.py3-none-any.whl, et_xmlfile-2.0.0-py3-none-any.whl, a PyYAML-…whl, and a chardet-…whl.
  2. Copy the whole wheelhouse folder to the server, for example with scp -r wheelhouse user@server:~/.
  3. On the server, install into your home folder without touching the network:
    server
    [ -x ~/venv/bin/python ] || python3 -m venv ~/venv
~/venv/bin/pip install --no-index --find-links ~/wheelhouse "configmergetool[encoding]==3.0.2"
~/venv/bin/configmergetool --version
    Then link the command onto your PATH as in method A step 3.
PyYAML and chardet are built per platform

openpyxl, et_xmlfile and ConfigMergeTool are pure-Python wheels (py3-none-any), so they install on any OS. The PyYAML and chardet wheels you download match the downloading machine: a Mac downloads a macosx_arm64 build, for example. For a Linux or Windows server, either run the download on a machine with the same OS and Python version, or tell pip the target, for example --platform manylinux2014_x86_64 --python-version 3.11 --only-binary=:all:.

If chardet doesn't fit, leave out [encoding]. The tool still works, reading files that aren't UTF-8 as latin-1.

RHEL 8 needs a newer Python first

RHEL 8's default python3 is 3.6, which is too old. The administrator installs one once: sudo dnf install python39 (or python3.11 / python3.12). RHEL 9's default Python 3.9 works as is. If the script says the environment could not be created on RHEL 8 with Python 3.11/3.12, the system libraries are older than the Python package; sudo dnf update expat fixes it.

Tested with the network cut off on Rocky Linux 8.9 and 9.3 (RHEL-compatible), on x86_64 and aarch64, with Python 3.9, 3.11 and 3.12, including an audit and a merge.

Upgrade and uninstall

Upgrade to a newer wheel

For example, from 3.0.1 to 3.0.2. Your venv, PATH link and run history stay as they are.

macOS / Linux
~/venv/bin/pip install --upgrade "configmergetool-3.0.2-py3-none-any.whl[encoding]"
windows powershell
& "$env:USERPROFILE\venv\Scripts\pip.exe" install --upgrade "configmergetool-3.0.2-py3-none-any.whl[encoding]"

Finish any open audit and apply its patch before upgrading. Patches are applied against the files the audit read.

Uninstall completely

  • Method A or C: run ~/venv/bin/pip uninstall configmergetool and remove the ~/.local/bin/configmergetool link. If the folder holds nothing else, you can delete the whole folder instead (~/venv, or %USERPROFILE%\venv on Windows).
  • Method B: python3 -m pip uninstall configmergetool openpyxl et_xmlfile chardet. Only remove the libraries if nothing else of yours uses them.
  • Optionally, delete ~/.configmergetool/, which holds the audit run history.

UseWhat the tool does

ModeUse it toStarted by
AuditCompare the same configuration across several nodes (Staging, Prod, DR, …), flag drift, and fix it from an interactive HTML report.--audit-config-file
Apply patchWrite the corrections you chose in the audit report as new config files.--apply-audit-patch
MergeCarry a site's customised settings (base) onto a new software release's defaults. Base values win.--base-dir / --base-config-file with --release-dirs

The tool only reads the node, base and release folders. It writes to reports/ and the output folder you name, and it refuses an --output-dir that overlaps an input folder.

Audit nodes for drift

  1. Put a copy of each node's configuration in its own folder, e.g. STG/, PROD/, DR/.
  2. Describe the nodes in audit.json. The first node is the reference that others are compared with. output_dir is where applied patches are written:
    audit.json
    [
  { "base_dir": "STG",  "name": "Staging" },
  { "base_dir": "PROD", "name": "Prod-Site" },
  { "base_dir": "DR",   "name": "DR-Site" },
  { "output_dir": "corrections/" }
]
    base_dir paths are relative to the folder you run the command from. Node names must be unique. Never put a literal "password" in this file; use "password_env" (the name of an environment variable) instead.
  3. Run the audit from the folder that contains the node folders:
    terminal
    cd ~/audits/helm-site
configmergetool --audit-config-file audit.json \
  --filter-file filter.txt \
  --mapping-file Mapping.cfg \
  --quiet
    --quiet prints only differences, warnings and the summary. Leave it out to see progress. Every file used here is described in the config file reference.
  4. Open reports/audit_YYYYMMDD_HHMMSS/audit_report.html in your browser.

How each file type is compared:

File typeComparison
.properties .cfg .ini .confKey by key, section by section, against the first node that has the file. Commented-out keys count as present (commented).
.jsonValue by value, by dotted path (server.port).
.sstpRouting-rule blocks, compared on their original text across all nodes. Only whitespace is ignored; comments count. A block missing on a node and changes outside any block are mismatches. The row label (VALUE, ORDER, TEXT_DIFF, BLOCK_ABSENT) is informational only.
.yaml .yml (e.g. Helm values.yaml)By structure, one row per parameter, so order never matters. Maps are matched by key; list entries by their first field (appcfg.props[opt=kpi.stats.rotate.interval].val); plain value lists as sets. The same entry in two sections is two rows. Instance blocks (- inst: 2) pair by position, and a differing id shows as instance-specific. Comments on only some nodes get one (comments) row. Files with template code ({{ }}) or invalid YAML use the line comparison below.
tpl, xml, txt, md, sh and other textWhitespace is ignored. When content differs, each changed block of lines becomes one mismatch row (new in 3.0).
Binaries (jar, tgz, crt, …)SHA-256 checksum and size. Excluded unless your filter file lists their extension.

Backup copies such as values.yaml_bkp200821 are skipped automatically, but only when the original file sits next to them. They're listed in feedback/skipped_backups.json.

In a Helm chart, values.yaml is the final version. Any other file whose name contains "values" (values_DR.yaml, unedit_values.yaml, values_DRA1.yml, values.yamlbck, …) is skipped as a backup when a values.yaml sits in the same folder. values.schema.json is part of the chart and is still audited. List a file in no_skip_files to audit it anyway.

Compare files stored at different paths

New in 3.0. When a file lives at a different path on another node, such as Staging running one chart dra-SA while Prod and DR run two instances dra-SA-1 and dra-SA-2, pass a mapping file with --mapping-file. Without it, those files are reported as absent.

Mapping.cfg
# whole folders: every file below is paired
STG/dra-SA=PROD/dra-SA-1
STG/dra-SA=PROD/dra-SA-2
STG/dra-SA=DR/dra-SA-1
STG/dra-SA=DR/dra-SA-2
# single file (overrides a folder line for that file)
STG/smartstp/values.yaml=PROD/smartstp0/values.yaml
  • The format is one LEFT=RIGHT pair per line. # starts a comment, and a leading / is ignored.
  • The first path part names the node: its base_dir, the last folder of it, or its name.
  • The left file appears in the report row of the right path. The Staging copy is therefore compared in both the dra-SA-1/… and dra-SA-2/… rows, and the Staging-only dra-SA/… row disappears.
  • A pair whose file exists on only one side is skipped and listed in audit.log as CMT-AUD-W011. A pair missing on both sides (hidden, filtered or binary) is skipped silently.
  • A line that names no known node stops the run with CMT-CLI-E018.

Choose which files are audited

Without --filter-file, every non-binary file is audited. A filter file holds one rule per line and is case-insensitive:

filter.txt
# include by extension
yaml
yml
tpl
properties
# include only named files of a type
conf::sysctl.conf,sctp.conf
# exclude a name (file or folder), a glob, or a subtree
!nohup.out
!*.swp
!logs/archive
# force-include a path inside an excluded folder
+logs/archive/current-session

Rules are applied in this order: force-includes (+), then excludes (!), then includes. Once a filter has any include rule, files it doesn't match are skipped. Archives, keystores, certificates and compiled files are skipped by default; list their extension (e.g. jar) to audit them by checksum. Skipped files are recorded in feedback/filtered_files.json.

Reading the audit report

  • Sidebar: files with differences or missing nodes are listed first. Ctrl+K searches file names.
  • Row colours: yellow means the value differs, teal is an instance-specific value (not counted as an error), purple is an expected difference, blue is a pending change, and a striped cell means the file is absent on that node.
  • Mapped nodes show ↪ original/path next to the node name. That node's download uses its own file name.
  • Text files list each changed block (e.g. L88–L91) under File checksum. Show scrolls the side-by-side view, where the lines that differ on each node are highlighted with line numbers. Text rows are read-only: download the node's file to edit it.
  • SSTP files show each node's original block lines, exactly as in the file, followed by the same side-by-side view. They are read-only too.
  • Show differences only hides matching rows. For text, XML and SSTP files it also trims the side-by-side view to the changed lines with 3 lines of context, lined up across nodes; skipped stretches show as ⋯ N unchanged lines, and a node without a line shows no line here — between L16 and L17. Files that exist on only one node show just the "absent" banner.
  • Prev / Next steps through every mismatch in the report. Use Skip to set aside a row you've reviewed.
  • For KV and JSON rows, Use for all or Override records a correction. Export Patch saves them all as a JSON file.
  • Export Diffs XLSX opens audit_diffs.xlsx, the same findings as a spreadsheet.

Large runs (over 22 MB) are split into parts audit_report_p01.html, …p02.html behind an index page.

Apply the fixes

Click Export Patch in the report. It saves a file such as audit_patch_2026-09-25T1015.json. Apply it from the folder the audit ran in, because source files are found through the node folders stored in the patch:

terminal
configmergetool --apply-audit-patch audit_patch_2026-09-25T1015.json --output-dir corrections/

Without --output-dir, the files go to output_dir from the audit config (pass --audit-config-file) or from the patch, and otherwise to <run folder>/corrections. Corrected files are written to corrections/<node>/<path>. The original node folders are never modified, and corrections.log lists every change. Review the files, then deploy them to the nodes yourself.

Merge a site's settings into a new release

terminal
configmergetool --base-dir base --release-dirs release --output-dir output --dry-run
configmergetool --base-dir base --release-dirs release --output-dir output
  • Base values win. A key in both folders takes the base value. A base-only key is added (unless --exclude-params-in-baseonlyconfig is set), and a release-only key is kept.
  • Release-only files are copied to the output. Files named differently in base and release are paired with --mapping-file using base/path = release/path lines.
  • Use --copy-baseonlyconfigfile for files to copy verbatim from base, such as keystores and licences.
  • YAML files (Helm values.yaml) are merged the same way: a differing value is rewritten with the site value where it stands in the release file, site-only keys and list entries are added in the same section, and the release file's layout and comments are kept. Entry order doesn't matter. A site value that can't be placed (for example into an inline list like pullSecrets: [a]) is left for review (CMT-MRG-W018). Templates with {{ }} keep the release copy.
  • Backup copies (values_DR.yaml, *.p12_bck1sep, …) are neither merged nor copied to the output; the report lists them.
  • Use --base-config-file bases.json to merge several nodes in one run (one pass per base).
  • --dry-run analyses and reports without writing output.

Base config --base-config-file

Merges several bases against the same release in one run. When given, --base-dir, --mapping-file and --copy-baseonlyconfigfile are ignored. With two or more entries, each base's files go to output/<name>/ and get their own merge_report_<name>.xlsx.

FieldTypeRequiredMeaning

  { "base_dir": "base/node2", "name": "prod-us" }
]

Filter file --filter-file

One rule per line, case-insensitive. The first matching step decides: + force-include, then ! excludes, then include rules, then the built-in binary types. With no include rules, everything else is audited; with any include rule, unmatched files are skipped.

RuleExampleEffect
Extensionyaml · .xml · noextEvery file with that extension (noext = files without one).
Extension::namesconf::sysctl.conf,sctp.confOnly these file names.
Extension::foldershtml::runtime,testFiles of that type inside folders with these names (items without a dot).
Folder pathconfig/routingEverything below that path.
GlobGTPProxy* · config/*.xmlNames matching the pattern; with /, the whole relative path.
Exclude!nohup.out · !*.swp · !logs/archiveA name (file or folder), a glob, or a subtree.
Force-include+logs/archive/currentRescues a path from an exclude. Not an include rule.
Binary typesjar · crtArchives, keystores, certificates and compiled files are skipped by default; listing the extension audits them by checksum.

Audit mapping --mapping-file

LEFT=RIGHT per line. Each side starts with a node prefix (full base_dir, its last folder, or the node name). A folder side maps every file below it; a file line wins over a folder line. The left file joins the report row of the right path. See Mapped paths for the full behaviour.

Mapping.cfg
STG/dra-SA=PROD/dra-SA-1
STG/dra-SA=PROD/dra-SA-2
Staging/smartstp/values.yaml=DR-Site/smartstp1/values.yaml

Merge mapping --mapping-file

base_path = release_path per line, for files named differently in base and release. Paths may start with the folder path, its last name, or be the path inside the folder; lines without = are ignored. Several base files mapped to one release file merge in line order, and the first wins on shared keys. One base file mapped to several release files is merged into each.

mapping.txt
base/config/fsmapp.cfg = release/config/app.properties
base/config/db-primary.properties = release/config/database.properties
base/config/db-replica.properties = release/config/database.properties

Copy-only list --copy-baseonlyconfigfile

One base file per line, copied to the output unchanged: licences, keystores, certificates. The same path forms as the merge mapping are accepted, and paths that lead outside the base folder are skipped with a warning.

copy-only.txt
base/config/ssl/server.keystore
base/config/licence.dat

Audit patch --apply-audit-patch

Written by Export Patch; you don't normally edit it. Top-level fields: audit_run, exported_at, node_dirs (node → folder, used to find source files), output_dir, run_dir, changes, and skipped (record only). Each change carries file, file_type (kv or json), node, compound ([Section]|key or a dotted JSON path), key, section, original, corrected and action (modified or added).

{
  "audit_run": "20260925_101203",

Troubleshooting

You seeCause and fix
configmergetool: command not foundThe command's folder isn't on your PATH. Run it by full path (~/venv/bin/configmergetool) or follow method A step 3. Open a new terminal afterwards.
error: externally-managed-environmentYour Python blocks pip --user and system-wide installs. Use a home-folder venv (method A).
ensurepip is not available / No module named venvDebian/Ubuntu ship venv as a separate package, python3-venv. Ask your administrator to add it, or use method B if your Python allows it.
No module named openpyxlYou're running a different Python from the one you installed into. Use the venv's own configmergetool or python, or reinstall into the Python you run.
Old version or old output after upgradingRun configmergetool --version. A source checkout (method D) needs git pull, and an older copy may come first on your PATH (which -a configmergetool, or where configmergetool on Windows).
[CMT-CLI-E010] base_dir does not existbase_dir in audit.json is relative to the current folder. cd into the folder that holds the node folders, or use absolute paths.
File reported absent on a node that has it under another pathAdd a mapping file. Check audit.log for CMT-AUD-W011 lines about pairs that didn't match.
Accented or special characters look wrongInstall chardet ([encoding]), so files that aren't UTF-8 are decoded with their real encoding.
PowerShell won't run Activate.ps1Run Set-ExecutionPolicy -Scope CurrentUser RemoteSigned (no admin needed), or skip activation and call …\Scripts\configmergetool.exe directly.
